How a round works

Four steps, each checkable from chain data.

01

Commit

Entries lock on-chain before any randomness exists.

02

Seed

Poseidon hash of the 8 slot hashes after sales close.

03

Attest

Staked nodes vote; the program re-derives the winner and rejects wrong votes; 2/3 threshold.

04

Verify

Anyone recomputes the result from chain data.

02 / GUARANTEES

Guarantees

What the program enforces, not what we promise.

Deterministic draw

Winner re-derived by the program; wrong votes rejected.

proof ↗

Liveness slashing

A node that skips its vote can be slashed 10% of stake by anyone.

proof ↗

Zero-knowledge winners

Private-round winners proven in Halo2, verified natively on Solana (no Groth16 wrap).

proof ↗

Pinned setup

The verifier only accepts the Perpetual Powers of Tau SRS; foreign-setup proofs are refused on-chain (error 0x104).

03 / DEVELOPERS

For developers

Mirror the rules off-chain.

The TypeScript SDK in the repo (sdk/) implements the same seed derivation and winner rule the program enforces, so you can recompute any round from your own RPC.

typescript 
import { fetchSeedWindow, computeSeed, deriveWinnerIndex } from "./sdk/src/seed";
const win = await fetchSeedWindow(connection, endSlot);
const seed = computeSeed(win.hashes, roundId, ticketCount);
const winner = deriveWinnerIndex(seed, ticketCount); // same rule the program enforces

06 / ECONOMICS

How PRUV makes money

Fees are set in on-chain config, not in a pitch deck.

Protocol fee

5% of every pot goes to the protocol treasury, a Squads 2-of-3 multisig.

Node rewards

10% goes to the staked nodes that attest the draw. A node that misses its vote is slashed.

Next

Per-allocation fees for teams that run airdrops and allowlists on PRUV, starting with PruvDrop.

Current devnet config: winner 85%, nodes 10%, treasury 5%. Private rounds: winner 95%, treasury 5%.
